# 微信日报 Oracle 实验协议 v1

## 1. 目的

本实验只回答一个问题：当前日报质量损失主要来自交流重建、内容选择、人物归因，还是最终成稿？

在完成本实验前，不修改生产链路，不增加固定输出长度，不调整候选上限，也不把 9 月 16 日单日效果当作泛化证据。

## 2. 固定输入

- 原始日级消息数据库及其 SHA-256；
- 无模型交流过程重建产物；
- 语义内容线抽取产物与失败清单；
- 当日 ACU 双轮标注和仲裁版本；
- 当前生产/实验报告作为 B0；
- 模型、提示词、配置、时间窗口和时区记录。

同一次比较中除被研究因素外，其余输入和配置必须保持一致。

## 3. 实验条件

### B0 当前基线

复现当前完整路径。记录候选召回、最终选择、关系错误和 fallback 行为。

### O-R Reconstruction Oracle

用人工修正的交流边界、上下文和对象归属替换系统重建；选择与成稿保持 B0 不变。

比较：

- must ACU 是否更容易被召回；
- E1/E4 是否下降；
- 人物槽位是否间接改善。

### O-S Selection Oracle

直接向 B0 成稿模块提供人工标注的 `must` ACU；不允许模型重新决定是否纳入。

比较：

- 最终 must ACU 覆盖；
- E2/E3/E7/E10；
- 用户任务正确率。

如果 O-S 仍然错误，则不能把问题继续归咎于选择器。

### O-G Generation Oracle

保留 B0 选择结果，由人工只做忠实改写，禁止补充或删除内容。

比较：

- 琐碎率是否仍高；
- 关系和事实错误是否消失；
- 可读性和任务效用是否改善。

如果人工忠实改写仍然琐碎，说明上游选择错误。

### B1 扁平 Query Baseline

不用复杂交流重建，以聊天边界和时间顺序提供消息；用同一用户问题定位并摘要。用于检验现有重建相对简单方法的真实收益。

### B2 Reconstruction + Query Selection

保留现有重建，只让选择器回答用户日报问题；不增加新聚类器和固定篇幅。

## 4. 用户日报问题

所有 query-conditioned 条件使用同一任务描述：

> 根据这一天的微信记录，找出会改变用户行动、决定、风险判断、对重要外部变化的认识，或值得长期保留的方法与资源的信息。保留人物、动作、对象和状态；将个人体验、观点、问题和事实分开。不要因为私聊、@用户、出现日期或存在链接就自动纳入。报告长度由通过纳入判断的信息自然决定。

实验期间不得针对某一天改写该问题。

## 5. 评估流程

1. 用评测工具对每个条件计算独立指标；不得合成总分。
2. 对每一天输出 E1-E10 错误分布。
3. 做逐日配对比较；同时报告平均值、中位数和 bootstrap 置信区间。
4. 进行用户任务评估：变化识别、行动判断、证据定位和关系理解。
5. 记录模型调用次数、输入输出 token、运行时和失败率。
6. 对指标改善最大的条件进行人工盲评，隐藏系统名称和顺序。

## 6. 结果解释

- O-R 大幅改善：优先修交流过程边界或对象归属。
- O-S 大幅改善且 O-G 改善有限：优先修内容选择。
- O-G 大幅改善且 O-S 仍出错：优先修归因和成稿。
- B1 不劣于现有重建：停止继续增加重建复杂度。
- B2 胜过 B0：优先采用 query-conditioned selection 这一最小改动。
- 任何方案若提高覆盖却增加关系方向或无证据结论，不得视为成功。

## 7. 进入生产的条件

不预设单一数值门槛。进入生产需要：

- 在时间隔离盲测中逐日多数改善；
- 改善的置信区间和错误案例不由单日驱动；
- 人物关系、证据忠实和隐私没有实质性退化；
- 改善可由消融实验归因；
- 维护成本与调用成本没有明显超过质量收益；
- 用户盲评更偏好新结果，并能更准确完成日报相关任务。
