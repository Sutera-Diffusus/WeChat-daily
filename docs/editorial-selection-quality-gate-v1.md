# 微信日报全局编辑与质量门方案 v1（已废弃）

> 本方案因预设输出条数、栏位配额和未经验证的系统分层，于 2026-09-18 废弃。后续以 `daily-brief-research-roadmap-v2.md` 的假设检验、oracle 实验和盲测路线为准。

## 1. 结论

现有系统不缺消息抓取、交流过程重建或单卡内容理解，真正缺少的是一层独立的“全天总编辑”。

当前链路会让每张交流卡分别判断自己是否重要，但“单卡重要”不等于“值得进入今天的日报”。结果是：

- 392 张成功内容卡仍然需要人工从头筛选；
- 私聊中的明确回复容易压过更重要的跨消息趋势；
- 有证据的琐事被误当成高价值内容；
- 同一事项被拆成多个待办，或不同对象因宽泛词语被错误合并；
- 最终压缩器面对的是少数上游误选卡，无法挽救召回阶段已经丢失的内容；
- 门禁全拒绝后，系统退回本地规则候选，把实验回退结果伪装成了可读日报。

方案不是继续调整一个总提示词，而是把“重建、理解、候选化、全局选择、成稿、验收”拆成可缓存、可审计的六层。前三层保留已有优化，后三层重做。

## 2. 从既有产出保留什么

### 2.1 保留

1. `ContentLedger -> ConversationEpisode -> ConversationFlow`：以交流过程而不是孤立消息为最小语义单位。
2. message ID、chat、speaker、时间、回复和媒体状态的权威边界。
3. 内容线的逐项证据绑定、主证据与上下文证据分离。
4. 不同对象必须拆线；只有共同回答同一上位问题时才允许合并。
5. `claim_type`、外部核验要求、不确定性和隐私标记。
6. 9 月 7 日简报的编辑结构：少量主线、变化解释、用户意义、证据索引和被过滤内容说明。

### 2.2 停止沿用

1. 不再把 `primary_insights` 的规则分数直接当作日报排名。
2. 不再以“与我相关”或私聊身份自动提升优先级。
3. 不再让每张交流卡独立决定自己是否进入日报。
4. 不再用固定 `limit=120` 的候选截断代表全天覆盖。
5. 不再在模型门禁全拒绝后，用零散本地候选生成正式日报。
6. 不再把人员名单、维修提醒、普通问卷、单句体验和链接集合铺成主正文。

## 3. 新链路

```text
原始消息
  -> L0 权威消息账本
  -> L1 交流过程重建
  -> L2 单过程内容线抽取
  -> L3 故事候选生成与同对象聚合
  -> L4 全天全局编辑选择
  -> L5 成稿与证据复核
  -> L6 版式和发布门
```

L0-L2 复用现有实现。新增的核心是 L3-L6。

## 4. L3：故事候选，而不是消息候选

每个候选必须有以下结构：

```json
{
  "story_id": "stable-id",
  "subject": "对象",
  "change": "当天发生的变化、决定、结果或形成的分歧",
  "user_impact": "为什么与用户有关；无则为 null",
  "status": "new|changed|decided|blocked|resolved|signal",
  "lane": "for_me|external_change|collective_signal|knowledge_resource",
  "claim_type": "chat_report|reported_experience|opinion|question|mixed",
  "evidence_refs": [],
  "conversation_flow_refs": [],
  "independent_speaker_count": 0,
  "privacy": "normal|private|sensitive",
  "uncertainties": [],
  "scores": {}
}
```

### 4.1 同对象聚合硬规则

- 同一聊天中出现同一明确对象、连续问题或明确回复关系，才可聚合。
- 跨聊天聚合必须存在稳定实体或可审计的显式桥，不能只凭“价格、模型、工作、问题”等宽泛词。
- 家教编号、地点和课程时间不得因为数字、价格或“模型”等词误入 AI 主题。
- 人物关系方向存在冲突时，候选必须使用中性表达，不能猜测主客体。
- 宁江月事项应写为“用户与宁江月进行团组织关系转接工作交接”，除非后续证据明确且一致地支持单向关系。

### 4.2 候选准入条件

候选至少满足一项：

- 明确改变了用户需要作出的决定或行动；
- 有硬日期、明确指派或未闭环风险；
- 出现已确认的决定、结果、失败或状态变化；
- 同一明确对象获得两名以上独立参与者的连续反馈；
- 形成可解释的分歧，并且分歧影响选择或判断；
- 提供可复用且与用户当前目标直接相关的资源。

普通寒暄、表情、人员逐名状态、维修物流、无答案提问、单人情绪、纯转发链接和无上下文单句默认不准入。

## 5. L4：全天全局编辑选择

### 5.1 四个固定栏位

日报不再混排所有类型，而是在四个栏位中竞争：

| 栏位 | 内容 | 上限 |
| --- | --- | ---: |
| 对你真正有影响 | 需要决定、执行或防风险的事项 | 3 |
| 外部变化 | 产品、组织、活动或环境的明确变化 | 3 |
| 群体信号 | 同一对象的多人反馈、分歧或趋势 | 3 |
| 值得保存 | 可复用知识、方法或高价值资源 | 2 |

全天正文目标为 5-9 条。没有足够内容时允许少于 5 条，禁止为了版面补琐事。

个人名单、普通提醒和低价值状态进入“个人备忘”，最多 3 条，不参与主线排名。

### 5.2 可解释评分

每个故事候选按以下维度打分，模型给建议，规则复核可计算字段：

| 维度 | 范围 | 说明 |
| --- | ---: | --- |
| 用户影响 | 0-5 | 是否改变用户行动、决定或风险 |
| 变化强度 | 0-5 | 相比此前是否产生新状态、结果、决定或阻断 |
| 证据强度 | 0-5 | 直接证据、对象清晰度、绑定完整性 |
| 信息增量 | 0-5 | 是否超越常识、重复抱怨和已知背景 |
| 群体信号 | 0-3 | 独立发言者、持续时间、交叉印证 |
| 时效 | 0-2 | 是否临近日期或刚发生 |
| 可复用性 | 0-2 | 是否能支持后续决策或方法沉淀 |
| 不确定性惩罚 | 0 至 -5 | 因果不清、对象不明、仅单人体验 |
| 隐私/琐碎惩罚 | 0 至 -5 | 私密、个人名单、纯行政细节 |

总分只用于同栏位初排，不直接决定入选。全局编辑器必须同时判断重复、栏位配额和当天叙事完整性。

### 5.3 硬性淘汰

出现以下任一情况，不能进入正文：

- 标题无法回答“什么对象发生了什么变化”；
- 主体或交接方向存在冲突，却使用确定性措辞；
- 摘要中的任一关键判断没有直接证据绑定；
- 仅因时间相邻或宽泛词重合而跨对象合并；
- 只有问题，没有答案、决定、影响或可执行的核查路径；
- 只有一个人的情绪或体感，且对用户没有明确价值；
- 内容已闭环且不影响后续决策；
- 公开报告会暴露不必要的个人信息。

## 6. 两级缩减，解决 392 卡无法编辑的问题

### 6.1 Chat Editor

在每个会话内部，把内容线缩减成 0-3 个故事候选。它只负责：

- 合并同一交流过程的重复表达；
- 分开不同对象；
- 提取变化、决定、未决问题和证据；
- 给出“不入选”的明确理由。

预计把 392 张成功卡压到 30-60 个故事候选。

### 6.2 Day Editor

Day Editor 只读取 30-60 个结构化故事候选，不再读取原始 3,925 条消息。它负责：

- 跨会话同对象去重；
- 四栏位竞争与配额；
- 多样性控制；
- 生成 5-9 条入选项和不超过 3 条个人备忘；
- 为每个落选候选记录原因。

这样修改日报不需要再次发起 444 次模型调用。L0-L3 可缓存，只有 Day Editor 和成稿层需要重跑。

## 7. L5：成稿契约

每条正文固定四部分：

1. **标题**：对象 + 当天变化，不写“关于……的讨论”。
2. **发生了什么**：1-3 句，合并过程而不是按时间复述。
3. **为什么值得看**：只写与用户判断或行动有关的意义。
4. **边界/下一步**：未验证、缺失证据或最小行动。

主摘要只回答三个问题：

- 今天真正发生了哪 2-3 个变化？
- 哪一件事最值得用户处理或记住？
- 哪些内容只是信号，不能当事实？

人员清单、证据 ID、完整引用和统计全部下沉到折叠附录。

## 8. L6：发布质量门

### 8.1 零容忍

- 人物关系或行动方向错误：0。
- 不同对象污染合并：0。
- 无证据的确定性事实：0。
- 私密内容误入公开正文：0。
- 失败回退伪装成正式日报：0。

### 8.2 质量指标

以人工选出的每日 5-9 条为编辑金标准：

- `Precision@8 >= 0.75`：前 8 条至少 6 条值得进入正文。
- 高价值主线召回 `>= 0.80`。
- 琐碎内容进入正文 `<= 1` 条，目标为 0。
- 证据绑定完整率 `100%`。
- 重复主线率 `0%`。
- 关系方向错误率 `0%`。
- 每条入选项都必须有可解释的入选理由；每条高分落选项必须有落选理由。

### 8.3 固定回归集

建立三天固定回归集，不再凭“这版看起来还行”验收：

- 2026-09-07：验证个人硬任务、外部变化和群体信号能够共存。
- 2026-09-08：验证 AI 工具密集日的主题压缩、分歧保留和去重。
- 2026-09-16：作为纠错集，验证宁江月关系、跨主题污染、人员名单降级和琐碎项淘汰。

每次修改必须同时跑三天，不能只优化当天样例。

## 9. 失败回退

- 单卡抽取失败：隔离该卡，保留重试队列，不阻断其他卡。
- Chat Editor 失败：该会话进入“待审阅”，不把原始卡直接提升到 Day Editor。
- Day Editor 失败或输出 0 条：生成“暂无通过质量门的日报”，同时提供审阅链接；不再使用旧规则结果顶替。
- 关系方向冲突：自动降级为中性表述并进入人工复核。
- 外部事实未核验：可以作为“群体信号”存在，但不能写成平台事实。

### P1：再修关系和用户价值

1. 新增人物关系方向冲突检测和中性化规则。

3. 将个人名单和行政细节移动到独立备忘区。

### P2：最后做成稿与界面

1. 新增成稿契约和证据折叠区。
2. 显示入选理由、置信边界和落选统计。
3. 提供“有用 / 琐碎 / 关系错误 / 错误合并”四类反馈，进入下一轮回归评测。
