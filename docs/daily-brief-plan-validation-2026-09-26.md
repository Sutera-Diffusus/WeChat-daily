## 结论

**方案方向可继续，但不能按勘察报告的行动清单直接批量改生产。** 当前最可靠的判断是：生产日报与大部分研究管线分离，候选化存在固定上限，私聊和特定主题有规则特权，三份冻结样例均记录 `local_fallback`。现有实验选择器依赖人工金标，且 `production_blocked=true`，尚未验证为通用改造方案。

## 对改造动作的判断

1. **先固定可比较的评测输入。** 统一采用仲裁版 ACU；记录样本范围、代码版本、配置、模型和 fallback 状态。另从原始消息独立抽样，评估上游漏召回。不能用条件性金标宣布全量召回。
2. **先做 O-S 与 B1/B2 的隔离对照。** O-S 只替换人工选出的 must ACU；B1 使用扁平时间/会话输入；B2 使用现有重建。同一天同一问题、同一成稿器，分别报告内容、关系方向、证据、隐私、成本和失败率。O-G 的结果保留为单日诊断。
3. **把高风险改动拆开验证。** 对私聊 `for_me`、主题 45/65 分特权、Top-120 候选截断各做单因素消融。每项先检查 must 召回、琐碎纳入、私密内容进入公开正文的变化，再决定是否接入生产。
4. **明确失败状态属于独立产品修复。** 当 LLM 未被接受或无合格标题/主张时，界面应区分“规则摘要”和“AI 日报失败”；避免把 `accepted_headline_count=0` 当作内容质量合格的信号。可以独立实现，但须先定义当前纯规则日报的显示契约，不应直接隐藏全部内容。
5. **罐头标题和 story 去重需基于样本确认。** 统计实际触发频率与误导案例，再修有问题的路径；全删标题模板可能使无 AI 配置用户丧失可读日报。去重必须保留不同主体、状态和时间阶段。

## 进入生产的门槛

- 至少有多个时间隔离日期的逐日配对结果；不得仅凭 09-16 日单例。
- 必须提高重要内容覆盖或用户任务正确率，且关系方向、证据忠实、隐私边界不退化。
- 证明改进来自单一改动；人工 codebook 不算自动选择器能力。
- 失败和回退在 API 与界面可见，产物标注来源；研究产物不得自动替换用户当前日报。
